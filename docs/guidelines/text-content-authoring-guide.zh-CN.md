# 文本内容编写指南

## 文档用途

这份文档用于告诉设计师：

- 现在应该去哪个文本目录改什么
- 哪些文本支持数组随机
- 哪些文本是正文
- 哪些文本仍然是程序层固定句式

## 当前文本目录分工

### 1. 冒险者正文

放在：

- `config/text/adventurers/`

负责：

- `name`
- `title`
- `motive`
- `impression`
- `rumor`

适合：

- 固定角色文本
- 普通模板的人物原型文本

### 2. 任务正文

放在：

- `config/text/quests/`

负责：

- `title`
- `description`
- `lineTitle`
- `focusText`

适合：

- 任务标题
- 任务简介
- 任务线标题
- 任务焦点文本

### 3. 线索 / 发现 / 失败回报正文

放在：

- `config/text/intel/`

负责：

- 线索标题
- 线索正文
- 失败回报标题
- 失败回报正文

适合：

- 成功带回的线索
- 失败带回的信息
- 发现类回报

### 4. 接触事件文本

放在：

- `config/text/adventurer-introductions.json`

负责：

- 店里认识新人的外层文案
- 围绕任务被介绍认识的外层文案

### 5. 程序层固定日志句式

仍然在：

- `src/game/text/storyText.ts`

这里当前负责的是：

- “任务开始了”
- “任务失败了”
- “任务带回了一条线索”
- “后续任务解锁”

这些是程序外层句式，不是具体世界观正文。

## 什么支持数组随机

当前已支持数组随机的内容：

- 冒险者正文
  - `name`
  - `title`
  - `motive`
  - `impression`
  - `rumor`
- 任务正文
  - `title`
  - `description`
  - `lineTitle`
  - `focusText`
- 线索 / 失败回报正文
  - `title`
  - `content`
  - `lineTitle`
- 接触事件文案
  - 当前本来就是数组

## 数组随机的使用原则

数组随机的作用是：

- 让同一模板 / 同一任务多次出现时不那么死
- 提高文本量和可读性
- 保持原型一致但细节有变化

它不该用于：

- 写互相矛盾的人设
- 写互相矛盾的任务目的
- 把一个任务写成完全两回事

## 什么时候该写数组，什么时候写单条

更适合写数组的：

- 普通冒险者模板文本
- 会反复发布的任务正文
- 可重复获得的线索池
- 失败后仍可能多次出现的失败回报

可以先写单条的：

- 开场固定角色
- 一次性过场文本
- 当前还不确定是否会重复出现的内容

## 一个常见判断

如果你脑子里出现了这句话：

- “同模板的人怎么可能每次都这么说”
- “这任务每次都一模一样读起来太僵”

那这块通常就值得写成数组。

## 当前推荐工作流

### 改任务文本

去：

- `config/text/quests/`

### 改冒险者文本

去：

- `config/text/adventurers/`

### 改线索或失败回报文本

去：

- `config/text/intel/`

### 改任务结构和参数

去：

- `config/quests/`

### 改冒险者结构和参数

去：

- `config/adventurers/`

## 最低检查表

每次新增或修改正文，至少检查：

1. 这段文本是不是写到了正确目录
2. 如果会反复出现，是否应该写成数组
3. 数组内几条文本是否表达同一个原型
4. 如果是失败回报，是否真的有失败后的信息价值
5. 如果是任务标题 / 线索标题，是否能让玩家一眼区分它和同线其他内容
