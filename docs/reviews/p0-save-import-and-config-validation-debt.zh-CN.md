# P0 存档导入安全与配置校验技术债

## 记录目的

当前项目仍以玩法和序章内容开发为主，本轮不要求立即扩展存档 UI、引入完整校验框架或中断内容迭代。

但下列问题已经越过普通体验优化的范围：

- 不可信存档内容可能进入 DOM 字符串拼接路径
- 存档只做浅层结构判断，嵌套对象仍可能在恢复阶段触发异常
- 导入和启动读档缺少覆盖完整恢复流程的异常边界
- 本地持久化失败会被静默吞掉，界面仍可能报告成功
- 配置文件依赖 TypeScript 断言，缺少运行时结构与引用校验

这些事项统一记为必须回收的 P0 技术债。这里的 P0 表示一旦进入正式发布、公开分发存档或扩大人工配置规模，就不应继续带病推进；不表示当前内容开发必须立即停摆。

## 当前边界

### 已有基础

- 存档带格式版本，并保留迁移入口。
- 导入 JSON 解析失败或顶层版本不兼容时会拒绝导入。
- 部分基础数值和日志条目在恢复时会回退或过滤。
- 导入失败已有面向玩家的通用提示。
- 配置层已有 TypeScript 类型，编辑期能发现一部分字段错误。

### 尚未覆盖

- 当前版本校验主要确认若干顶层数组和对象存在，没有逐层验证任务、人物、线索、发现、日志和结果对象。
- 通过浅层校验的数据会直接进入迁移与恢复函数；嵌套字段类型错误、缺失或引用失效时，恢复过程可能抛出异常。
- 存档中的人物名、任务文本、日志文本等内容可能进入 `innerHTML` 模板，导入文件因此不能视为可信数据。
- `localStorage` 写入和删除失败会静默降级，调用方无法区分“状态已修改”和“状态已持久化”。
- JSON 配置通过类型断言进入运行时，没有统一检查重复 id、无效引用、数值范围和条件组合。

## P0 风险

### 1. DOM 注入

导入存档属于不可信输入边界。只要存档可编辑、可下载或可由其他人提供，其中的字符串就不能直接作为 HTML 片段渲染。

当前风险不只包括脚本标签。事件属性、可执行链接、破坏 DOM 结构的标签以及后续新增的富文本拼接点，都可能扩大影响面。

必须回收的原则：

- 默认使用 `textContent` 或等价的文本节点 API。
- 必须生成结构化界面时，由代码创建元素并分别写入文本。
- 只有明确声明允许富文本的字段才能进入清洗流程，且允许列表应尽量小。
- 不以“当前导出文件由本项目生成”作为信任依据，导入文件始终按外部输入处理。

### 2. 嵌套结构校验不足

顶层存在 `game`、数组或对象，不代表其中元素满足恢复函数的前置条件。

至少需要覆盖：

- 基础字段：版本、日期、计数器、金钱和认知等级。
- 任务：id、模板引用、状态、日期、奖励、进度、冒险者引用和结果对象。
- 冒险者：实例 id、模板 id、生成值、认知状态、当前任务引用和展示文本。
- 库存、线索、发现、日志：键、数量、类型、引用、日期、文本和枚举值。
- 集合约束：重复 id、计数器下界、悬空引用和互相矛盾的状态。

校验结果应能区分：

- 可迁移的旧版本存档。
- 可安全回退或过滤的非关键字段。
- 必须整体拒绝的结构错误。

不能依赖恢复函数在运行过程中顺便发现格式问题。

### 3. 恢复异常边界缺失

JSON 解析成功和浅层校验通过后，迁移、实例恢复、任务结果重建、引用修复和界面刷新仍可能抛出异常。

必须保证：

- 导入失败不会部分覆盖当前内存状态。
- 导入失败不会覆盖浏览器中最后一份可用存档。
- 启动读档失败时能回退到可用初始状态，并给出可理解的提示。
- 恢复、替换、持久化和首次渲染应按可回滚顺序执行。
- 玩家看到“导入成功”前，完整恢复流程必须已经完成。

建议先恢复到独立候选状态，完成校验和必要的派生数据重建后，再一次性替换当前状态。

### 4. 持久化失败反馈缺失

浏览器可能因为隐私模式、配额、权限、存储损坏或环境限制而拒绝 `localStorage` 操作。

静默吞掉异常会产生错误承诺：

- 玩家继续操作，但刷新后进度丢失。
- 导入后的内存状态可用，但实际没有替换本地存档。
- 清空操作失败，界面却显示已经清空。

持久化接口应返回明确结果，调用方据此显示成功、失败或“仅本次会话有效”。失败提示不能被后续通用成功提示覆盖。

## 配置校验风险

当前任务、人物、资源、线索、发现、名字池和文本池会继续随内容开发增长。TypeScript 类型断言只影响编译期，不会证明 JSON 运行时数据真实满足类型。

统一配置校验至少应检查：

- 所有要求唯一的 id 不重复。
- 模板、资源、线索、发现、名字池和文本池引用真实存在。
- 数值为有限数，整数要求、非负要求和上下界成立。
- `min <= base <= max` 等区间关系成立。
- 枚举值、解锁模式、结果类型和可见性值合法。
- `all / any` 条件非空且结构与语义匹配。
- 必填文本非空，文本池具备可用条目。
- 一次性模板、固定角色和特殊入口不存在互相冲突的配置。

校验应在开发和构建阶段提供可定位到文件、记录 id 和字段路径的错误。运行时仍应保留防御性检查，不能把构建校验当成导入存档校验的替代品。

## 建议验收项

### 存档导入

- 导入包含 HTML 标签、事件属性和恶意链接字符串的存档后，页面只显示纯文本，不创建可执行 DOM。
- 对每个嵌套集合分别测试 `null`、错误类型、缺字段、非法枚举、极端数值、重复 id 和悬空引用。
- 任一恢复步骤主动抛出异常时，当前游戏状态和原本地存档保持不变。
- 旧版本合法存档仍能经过迁移恢复，非法旧档被稳定拒绝。
- 超大文件、超深结构或超长文本有明确限制，不造成页面长期失去响应。
- 导入成功提示只在校验、迁移、恢复、持久化和首次渲染全部成功后出现。

### 本地持久化

- 模拟 `setItem` 抛出异常时，界面明确提示未保存，不显示成功。
- 模拟 `removeItem` 抛出异常时，界面明确提示未清空，并保持状态一致。
- 存储不可用时，玩家能看出当前进度仅在本次会话有效。
- 自动保存失败不会阻断当前操作，但会留下持续可见且不过度刷屏的状态提示。

### 配置校验

- 每类配置至少有一份合法样例和一组非法夹具。
- 重复 id、无效引用、错误区间和空文本池会使校验命令以非零状态退出。
- 错误信息包含配置来源、记录 id 和字段路径。
- 构建或 CI 必须运行配置校验，不能只依赖人工执行。
- 新增配置类型时，类型定义、运行时校验和非法夹具同时更新。

### 回归边界

- 合法当前版本存档导入、导出和刷新恢复行为保持一致。
- `v1` 到当前格式版本的迁移链有固定回归样例。
- 任务、人物、日志、线索和发现的普通显示不因转用安全 DOM API 而丢失内容。
- 配置校验不改变合法内容的运行语义，只阻止不合法内容进入构建或启动流程。

## 回收时机

允许当前继续以内容开发为主，但出现以下任一条件时，应先处理本记录中的相关 P0 项：

- 对外发布或允许玩家交换、上传存档。
- 存档导入从开发辅助功能转为正式玩家功能。
- 配置内容开始由更多人员长期并行编辑。
- 新增富文本、用户自定义文本或外部内容来源。
- 存档格式再次升级并扩大迁移范围。
- 项目建立公开构建或持续集成发布流程。

在这些条件出现前，可以分阶段落地；在条件出现后，不应继续把这些问题仅作为文档备注。

## 完成判定

只有同时满足以下条件，才可以关闭这份技术债：

1. 不可信存档字符串不再未经处理进入 HTML 拼接。
2. 当前格式与受支持旧格式都有完整的嵌套运行时校验。
3. 导入和启动恢复具备不会破坏现有状态的异常边界。
4. 保存、替换和清空失败能传递到 UI，并提供准确反馈。
5. 配置校验进入固定开发命令与 CI，覆盖唯一性、引用和范围规则。
6. 上述验收项有可重复执行的自动测试，关键失败路径不再只靠手工体验。
