# v0.13 随机冒险者代码审查

## 结论

随机冒险者的主流程已经形成闭环，可以作为本版玩家体验基础：

1. 世界事件或任务分流决定是否出现新人。
2. 根据来源和任务需求选择模板，也支持显式模板。
3. 模板生成姓名、正文、人格和能力。
4. 新人只生成一次，并取得独立实例 id。
5. 实例进入人物列表，任务引用同一个实例。
6. 实例最终值、置顶和任务关系进入本地存档。

本版可以结束，但不应把它表述为“完整人物生态已经完成”。

## 已修复问题

### 严重

- 普通模板原先生成一次后就会退出可用池，实际效果是“一个模板只能有一个人”。现在由 `spawnMode` 明确区分一次性和可重复模板。
- 任务新人承接原先先生成预览对象，触发接触时又生成第二个对象，任务状态可能写到未存储对象上。现在预览只用于评分，确认后只实例化一次。
- 多个同模板实例原先共用模板 `id`，会导致任务、置顶和查询冲突。现在运行关系统一使用独立实例 id。
- 生成冒险者置顶信息原先可能在读档恢复顺序中被过滤。现在先恢复实例，再校验置顶关系。

### 中等

- 原中心采样使用高度相关的种子，实际接近均匀分布。现在使用同一确定性伪随机序列的三个独立采样值形成中心集中分布。
- 任务路径可以绕过“每天最多一次新人接触”的限制。现在任务候选分流会读取当天接触记录。
- 旧存档的任务和置顶引用会继续指向模板 id。存档 `version: 5` 会迁移为实例 id。
- 旧版锚点角色迁移查询使用了新实例 id，无法匹配旧模板 id。现在增加模板 id 回退。

## 仍未达到的完整预期

### 中等

- `AdventurerInstance` 仍继承整个 `AdventurerTemplate`，因此存档快照会携带 `spawnMode`、生成区间、名字池引用等模板编写字段。当前不影响正确性，但长期应拆成明确的实例事实快照，避免模板参数和人物状态继续混写。
- JSON 配置依赖 TypeScript 断言，没有运行时结构校验。缺字段、重复 id、错误区间或无效引用可能直到运行路径触发时才暴露。
- 新人出现与任务分流的调参仍写在代码常量中，缺少长期统计基线。当前公式满足软人数区间和深区锁定，但还不能证明长期节奏已平衡。
- 当前内容只有三个普通原型和一个名字池。机制允许无限实例，不代表内容重复度已经达到正式版本要求。

### 低

- 人物没有离开、隐退、事故和长期不可用状态，因此人数只会增长，不会形成完整生态循环。

## 实现与文档对账

### 原先只有实现、文档不足

- `spawnMode` 的一次性/可重复语义
- 递增实例 id 计数器
- 预览候选与正式实例只生成一次的边界
- 存档 `version: 5` 的关系迁移

以上已补入本版文档、冒险者设计守则和参数百科。

### 文档存在但尚未实现

- 地区、设施、任务结果驱动的模板池变化
- 冒险者流失、离开、隐退和事故
- 人物成长、关系深化、阵营和黑化
- 配置文件自动校验工具
- 完整人物数量与任务承接统计基线

这些属于后续版本，不应为了“少留坑”继续扩大 `v0.13`。

## 当前验证方式

- 生成范围、中心分布、实例 id 和模板复用规则直接检查正式公式与边界。
- TypeScript 编译和生产构建检查模块、类型和配置引用。
- 任务接取、人物显现和存档恢复通过正式序章内容进行玩家流程体验。
- 不再维护独立测试任务矩阵、批量模拟器或浏览器自动测试脚本。
