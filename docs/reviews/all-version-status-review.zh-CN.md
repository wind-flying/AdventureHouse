# 全版本功能状态审查

审查基准：

- 当前分支：`feat/v0.13-random-adventurers`
- 当前代码优先于旧版本文档
- 后续版本覆盖旧实现后，以当前最终行为判断旧目标是否仍成立
- “曾经完成”不等于“当前仍可独立验收”

## 主要发现

### 高优先级

#### 1. `v0.9` 与 `v0.10` 的技术测试资产已正式退役

`v0.13` 内容重构删除了旧技术角色和任务矩阵。当前结论是：

- 接取与结算公式本体继续保留
- 理论结果直接从公式、输入区间、连续性和上下界计算
- 不再通过批量随机模拟重新估计公式已经明确给出的成功率
- 不再维护与正式序章内容并行的技术任务配置

旧迭代文档继续保留当时的开发过程，但相关命令不再属于当前项目能力。

#### 2. `v1.0` 仍只有部分故事支撑

已经具备：

- 固定角色 A
- 玩家通过金钱发布任务
- 任务由人物自主承接
- 随机认识新冒险者
- 线索、发现、资源和序章任务链
- 冒险者能力会影响接取和结果

尚未具备：

- 正式饭店或据点经营玩法
- 从开店到建立私人机构的过程
- 属性升级宝物
- 冒险者成长与定向培养
- 核心人手形成机制
- 地区 C 或等价地区推进
- 最终冒险故事的阶段性收束

当前版本可以作为 `1.0` 的底层原型，但不能称为 `1.0` 主故事已经可玩。

### 中优先级

#### 3. 旧测试文档已转为历史归档

`testing-artifacts.zh-CN.md` 保留过去的测试字段、主题和旧文件路径，但已明确标记为历史记录。当前配置指南不再列出已删除的测试字段或兼容别名。

#### 4. `v0.13` 改变了 `v0.10` 的上层问题边界

`v0.10` 原先只在已知候选人中解决：

- 是否考虑任务
- 谁更可能接任务

`v0.13` 新增：

- 今天是否有人接
- 熟人、新人、无人接之间的渠道分流
- 新人模板如何受任务需求影响

这不是推翻 `v0.10`，而是在其上增加路由层。当前代码仍复用 `taskAcceptance.ts`，但新增的：

- `QUEST_TAKER_ROUTING_TUNING`
- `APPEARANCE_TUNING`

尚无与旧公式指南同等详细的独立公式文档。

#### 5. 存档导出命名已修正

导出文件名现在显式使用存档格式版本：

- `adventure-house-save-format-5-day-*.json`

避免把游戏版本与存档格式版本混写。

#### 6. 配置内容缺少自动结构校验

当前通过 TypeScript 类型断言加载 JSON，但不会在运行时系统检查：

- 重复模板 id
- 无效模板引用
- 无效线索引用
- 数值区间上下界
- `base` 是否位于 `min/max` 内
- 文本池或名字池引用是否存在

随着任务和人物内容增加，这会成为主要维护风险。

#### 7. 组合解锁的显示判断已修正

正式发布列表通过 `isQuestTemplateUnlocked` 正确处理：

- `unlockMode: all`
- `unlockMode: any`

消息板状态和任务完成日志现在都会先确认：

- 当前结果确实触发了相关条件
- 模板的完整 `all/any` 条件已经满足

不会再因为命中单个条件就提前提示后续已解锁。

## 逐版本结论

### `v0.1 Day Loop`

解决的问题：

- 建立按天推进的最小游戏循环
- 让收入、任务和日志发生可见变化

当前实现：

- `advanceDay` 仍负责日期、收入、任务板、人物显现和日志编排
- 下一天按钮仍会保存并渲染新状态

后续变化：

- 原先仅预留的冒险者和存档结构已经在后续版本落地

遗留：

- 一天内操作次数仍无正式约束
- 时间仍只有“天”，没有日内阶段

判定：已完成。

### `v0.2 Single Screen UI`

解决的问题：

- 将主要操作集中到单一应用壳
- 拆分 UI、样式、文本和业务入口

当前实现：

- 桌面端仍为导航、内容、动态三栏
- 小屏会切换为单列
- CSS 仍按基础、布局、组件分层

后续变化：

- 页签从早期功能扩展到任务、人物、消息板、库存、日志

遗留：

- 筛选区没有实现 sticky
- 长列表没有分页或“加载更多”
- 当前没有成功执行的浏览器布局回归测试

判定：主目标完成，UX 遗留未收。

### `v0.3 Adventurer Acquaintance`

解决的问题：

- 任务不再由匿名单位自动完成
- 玩家只看到已经接触的人物
- 人物信息按认知逐步开放

当前实现：

- 任务保存冒险者实例 id 与名字
- 人物页只显示已进入玩家视野的人
- 日志会显示具体人物

后续变化与原因：

- 固定冒险者配置被拆成固定锚点与可重复原型
- 原因是随机人物必须区分模板与长期实例

遗留：

- “听闻但尚未见过”的自然传播机制仍较弱

判定：已完成，人物来源模型已被 `v0.13` 正式升级。

### `v0.4 Resource Presentation`

解决的问题：

- 不再向玩家暴露资源内部 id
- 收口资源、状态和固定 UI 文案

当前实现：

- `resourceDisplay.ts`
- `statusText.ts`
- `uiText.ts`
- `uiLabels.ts`
- `viewModels.ts`

均仍在正式使用。

遗留：

- 更复杂物品、宝物和成长素材尚无展示模型

判定：已完成。

### `v0.5 Adventurer Personality`

解决的问题：

- 建立八项人格轴
- 让人格影响人物行为而不是只作为描述

当前实现：

- 八项人格进入任务接取
- 少量人格进入任务结算
- 认知等级控制人格标签数量
- 随机人物按模板生成有波动的最终人格

后续变化与原因：

- 接取公式从 `taskBoard.ts` 移到 `taskAcceptance.ts`
- 原因是正式公式需要被运行流程和模拟工具共享

遗留：

- 人格仍没有任务外生活行为、关系事件和长期变化

判定：已完成并深化。

### `v0.6 Task Shape`

解决的问题：

- 任务不再只是资源类型和数量
- 引入风险、性质、难度、耗时与模板展示

当前实现：

- 序章配置保留多种任务形状
- 发布表单、筛选和任务卡片仍读取模板属性

后续变化与原因：

- 旧技术测试任务被删除，改为序章世界观任务
- 原因是当前阶段需要玩家可体验内容，不再继续展示过期技术矩阵

遗留：

- 玩家可调参数仍主要只有预算和数量
- 没有组队需求和过程阶段

判定：系统目标完成，内容已替换。

### `v0.7 Acquaintance Depth`

解决的问题：

- 防止少量接触直接暴露完整人物
- 建立五级认知、接触点和置顶

当前实现：

- `heard / seen / acquainted / familiar / trusted`
- 接任务和完成任务增加接触点
- 新人引介会至少推进到“见过”
- 人物筛选和置顶仍可用

后续变化：

- 接触来源从任务扩展到饭店引介

遗留：

- 送礼、书信、生活事件等非任务交互不存在
- 认知依然不等于关系或服从

判定：已完成并扩展。

### `v0.8 Result Types`

解决的问题：

- 任务结果不再只有资源
- 建立线索、发现、消息板和任务解锁链

当前实现：

- `resource / lead / discovery`
- 结果按类型进入库存、线索或发现
- `questResult` 与 `intelReceived` 解锁条件仍在
- 成功、失败可进入不同后续任务
- `uniqueWhileOpen` 和结果后可见性仍在

后续变化与原因：

- 森林、河谷、矿道等旧测试主题被序章旧路线替换
- 功能结构保留，内容矩阵不再保留

遗留：

- 随机线索池没有去重、权重和最大出现次数
- 线索尚未直接更新玩家对同一任务的认知模型

判定：功能完成，历史测试内容已退役。

### `v0.9 Task Resolution`

解决的问题：

- 从强制测试结果升级为正式概率结算
- 分离人格和能力职责
- 建立任务隐藏特征、能力主场、线索修正和公式上下界

当前实现：

- `taskResolution.ts` 仍是正式结算入口
- 调查类任务仍使用成功率、能力、人格、线索和随机骰
- 日常资源任务仍按设计保持稳定成功

后续变化：

- 模块移动到 `systems/quests/`
- 技术角色和任务矩阵在 `v0.13` 内容重构时删除

遗留：

- 部分成功、伤病、死亡和中间过程仍未实现

判定：已完成；历史模拟工具已退役。

### `v0.10 Task Acceptance`

解决的问题：

- 将接任务拆成考虑阈值和候选竞争
- 用连续曲线、公共任务与筛选任务表达人物差异

当前实现：

- `taskAcceptance.ts` 仍控制熟人和新人候选评分
- 人格、能力主观判断、报酬、任务时长和近期状态仍参与接取

后续变化与原因：

- `v0.13` 在其上增加熟人、新人、无人接的路由层
- 原因是玩家不再预先认识所有可能接任务的人

遗留：

- 经济压力、义务和关系例外状态仍不存在

判定：已完成；历史技术矩阵已退役。

### `v0.11 Resolution Follow-up`

解决的问题：

- 将结果事实、原因解释和展示文案分层
- 从 `taskBoard.ts` 拆出结果生成与应用

当前实现：

- `taskResult.ts` 独立存在
- 存档只保存结果事实和内部原因标签
- `summary`、可见标签和展示覆写在运行时重建
- `resultInsightLevel` 控制可见解释数量

遗留：

- 信息掌握能力仍是孤立玩家字段
- 部分成功、伤病和过程事件没有落地

判定：已完成。

### `v0.12 Save System`

解决的问题：

- 浏览器本地自动保存
- 文本文件导入导出
- 存档格式版本和迁移入口
- 事实字段与可重建展示字段分离

当前实现：

- `localStorage`
- 导入、导出、清空
- `v1` 到 `v5` 迁移链
- 结果展示字段读档重建

后续变化与原因：

- `v0.13` 为独立人物 id 增加 `adventurerIdCounter`
- 存档格式升级到 `version: 5`
- 原因是可重复模板不能再使用模板 id 作为人物身份

遗留：

- 没有多槽位与云同步
- 存档校验较浅
- 人物快照仍携带部分模板编写字段

判定：已完成并完成一次真实迁移升级。

### `v0.13 Adventurer Instancing`

解决的问题：

- 模板不再等于人物
- 普通原型可以重复生成人物
- 新人物只在进入玩家视野时实例化
- 任务新人承接和饭店引介接入同一实例化入口
- 实例进入本地存档

当前实现：

- `unique / repeatable` 模板模式
- 随机或指定模板
- 随机名字、正文、人格和能力
- 递增稳定实例 id
- 预览候选与正式实例分离
- 同一天最多一次新人接触
- 存档恢复人物、任务和置顶关系

版本变化原因：

- 最初只计划建立模板/实例骨架
- 后续讨论确认玩家需要直接从项目中体验新人生成
- 因此本版扩大为完整第一版实例化闭环

遗留：

- 当前改动尚未提交
- 人物只增不减
- 模板池不受地区和设施正式控制
- 实例类型仍继承模板专用字段

判定：功能完成，工程收口尚差提交。

## 当前最合理的后续顺序

1. 提交并合并 `v0.13`。
2. 增加配置校验入口。
3. 再进入冒险者成长与宝物系统，使 `v1.0` 从“认识人”推进到“培养人”。

不建议当前直接做：

- 市场
- 完整关系系统
- 伤病、死亡和复杂中间过程一起上线
- 大规模新增随机模板

原因是当前最明显的缺口已经从“人物如何生成”转向“人物如何被长期培养并推动主故事”。
