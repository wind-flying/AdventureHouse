# v0.6 Task Shape

## 本次目标

把当前“资源表单式任务”升级为“任务模板式发布”，让任务开始拥有更清晰的形状，而不只是资源、数量和报酬。

## 本次范围

- 为任务模板加入标题、描述、风险和性质标签
- 新增几种用于测试的任务模板
- 把发布任务入口改成“选择模板后发布”
- 让任务卡片开始显示任务标题和性质信息
- 让人格权重对任务判断有更具体的落点

## 明确不做

- 完整主线任务系统
- 多阶段耗时模型
- 组队系统
- 圣堂任务
- 完整市场系统

## 关键规则

- 任务不再只是“资源采购单”
- 当前仍允许玩家调整数量和报酬，但前提是先选择任务模板
- 任务模板至少要表达：
  - 做什么
  - 风险如何
  - 性质偏稳还是偏异常
- 当前任务模板仍然服务于原型验证，不代表最终内容量

## 验收标准

- 当前任务发布不再是只选资源
- 至少有几种明显不同形状的测试任务
- 任务卡片能让玩家看出任务之间不是同一种东西
- 人格系统开始能基于任务形状而不只是资源偏好做判断

## 风险和待定问题

- 当前任务结果仍然主要落在资源与基础结算上，后续还需要继续扩展回报类型
- 任务模板数量如果太少，仍可能不足以支撑人格差异

## 跨版本待处理

- 后续应把任务模板进一步接到组队需求、固定耗时/可变耗时、主线碎片等系统
- 后续可能需要把“玩家可调部分”和“模板固有部分”再拆细
- 后续任务承接应区分“对任务类型的基础意愿”和“对具体任务实例的报价/数量修正”，避免同模板任务在同一天表现出过强的随机不一致
- 后续应逐步补足“任务特征维度”，例如稳定性、新奇度、纪律要求、社交要求、长线压力等，避免冒险者人格长期挤在少数几个任务标签上

## 结果记录

- 任务模板新增标题、描述、风险、性质字段，并补入多种测试任务
- 测试任务已在数据层显式标记 `contentStageTag: test`，并附带设计备注，避免后续误当正式文本
- 任务发布入口改成“选择模板后发布”，不再直接按资源类型填表
- 表单会展示模板简介、风险、性质和预估耗时
- 任务对象开始保存模板信息，任务卡片会显示标题、描述、风险和性质
- 人格承接逻辑开始基于任务风险与性质判断，而不只基于资源类型
- 任务页已加入按状态与性质的筛选，筛选项直接读取统一的任务分类定义
