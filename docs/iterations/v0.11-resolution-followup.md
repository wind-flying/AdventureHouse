# v0.11 Resolution Follow-up

## 本次目标

在 `v0.9` 的任务结算骨架和 `v0.10` 的接任务骨架稳定后，优先把“结果层 / 解释层”的最小正式结构收稳。

这版要解决的不是：

- 再次重调结算概率
- 提前做完整冒险过程
- 一次做完部分成功、伤病、长期代价

这版要解决的是：

- 任务回来后，系统最少需要记录什么结果结构
- 玩家后续要理解“为什么成 / 为什么败”，当前代码需要预留哪些正式接口
- 结果数据如何不再只剩一句 `summary`，而开始具备长期可保留的解释骨架

换句话说：

- `v0.9` 解决“任务到底怎么算”
- `v0.10` 解决“谁会接任务”
- `v0.11` 解决“任务结束后，系统如何正式表达发生了什么”

## 本次范围

- 正式收口任务结果数据结构
- 正式区分：
  - 结果事实
  - 玩家可见摘要
  - 解释原因
- 把当前 `taskBoard.ts` 里分散的结果生成与结果应用逻辑梳清
- 为后续更复杂结果层预留稳定接口

## 明确不做

- 重新校准 `v0.9` 结算公式
- 重新校准 `v0.10` 接任务公式
- 部分成功 / 部分失败正式实现
- 伤病与长期代价正式实现
- 任务途中事件链
- 更复杂的线索质量 / 线索来源系统
- 随机冒险者
- 随机任务
- 好感 / 关系深化
- 市场

## 关键规则

- 这版优先解决“结果结构”，不是“结果内容量”
- 当前正式结果不应再只依赖一条自由文本 `summary`
- 结果层至少要区分：
  - 客观 outcome
  - result kind
  - 结果摘要
  - 原因标签 / 解释标签
- 解释层必须服务于后续整体体验
  - 不是假设玩家单独玩过旧版本后才理解系统
- 这版的解释层不要求完全透明
  - 但必须让系统内部已经知道“哪些因素导致了这个结果”
- 结算结果与回传内容不应继续在 `taskBoard.ts` 中重复拼装
- 如果某项结果解释只能依赖未来中间过程系统，这版只留接口，不提前硬做

## 验收标准

- 任务结果已有正式数据结构，不再只靠 `QuestResult.summary`
- 结果生成逻辑与结果应用逻辑职责更清楚
- 当前成功 / 失败至少能挂出可长期保留的解释标签
- 这版完成后，后续要加部分成功、伤病、途中事件时，不需要推翻结果骨架

## 风险和待定问题

- 如果这版把“解释层”做成纯文本，会再次失去长期可扩展性
- 如果这版提前把部分成功、伤病、中间过程一起做进来，范围会再次失控
- 如果结果结构仍然过薄，后续随机人物 / 随机任务接入后，玩家只会看到更多黑箱结果
- 如果结果结构做得过重，又会把还没实现的系统硬绑进当前版本

## 跨版本待处理

- 存档骨架与数据版本化
- 部分成功 / 部分失败
- 伤病与长期代价
- 任务途中事件
- 更复杂的线索质量与来源
- 随机冒险者与随机任务
- 好感 / 关系深化
- 市场系统

## 结果记录

- 版本开始时先校正范围
- 当前已确认的起点问题：
  - `QuestResult` 结构过薄，目前只有 `type / outcome / summary`
  - `taskBoard.ts` 中结果生成与结果应用仍有重复拼装
  - 失败、线索、发现、资源的结果表达目前仍偏“即时文本”，长期结构不足
- 当前已落地的收口方向：
  - `QuestResult.details` 已开始区分内部原因标签与玩家可见原因标签
  - 玩家侧只读取稳定的正式评判标签，不再把 `resource / lead / discovery / failure` 这类结果事实混作原因解释
  - 冒险者与事件表述可以保留模糊，但结果解释层必须先提供一组稳定评判维度，作为理解其他模糊信息的基础
  - 玩家可见原因数量已预留为可成长接口：
    - `basic` 先不显示原因
    - 后续可按 `aware / trained / expert` 逐步放开 1 到 3 条正式解释
  - 玩家侧原因文案不直接暴露底层字段名，改为更正式、更文学化的解释句式
  - `capability / personality` 两类原因已推进为带上下文的正式解释：
    - 仍保留同一套正式标签
    - 但会结合任务性质和人选特征，给出更贴近“人”的说明
  - 结果摘要与 intel 文案已开始从结果事实重建，而不再把 `summary` 当唯一真相
    - 这为后续存档边界提供了更清楚的拆分：
    - 哪些字段属于长期结果事实
    - 哪些字段只是当前展示文案
  - `intelTitle / intelSummary` 已从结果事实层挪到展示覆写层
    - 当前结果结构已能在类型上区分：
    - 持久结果事实
    - 展示层需要的覆写文本
  - `primaryReasonTag / secondaryReasonTags` 已移除
    - 这两者只是 `visibleReasonTags` 的派生切片，不再单独保存
  - 当前新增待定点：
    - “信息掌握能力”已立成正式接口，但还没明确挂到哪条玩家长期资产线上
    - 顶层 `QuestResult.summary` 已开始显得偏冗余，但本版暂不强拆，避免扩大改动面
  - 当前版本收口判断：
    - 结果层骨架已足够稳定
    - `QuestResult.summary` 继续保留为兼容层
    - “信息掌握能力”留待后续挂到据点设施 / 固定资产 / 势力能力线，不在本版实现
