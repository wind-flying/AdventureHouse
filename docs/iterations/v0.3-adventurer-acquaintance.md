# v0.3 Adventurer Acquaintance

## 本次目标

引入第一版冒险者名册系统，但名册只显示玩家已经接触或听闻过的人，而不是直接给出完整人物列表。

## 本次范围

- 新增少量预设冒险者
- 引入“听闻 / 见过”等认知层级
- 让日常任务在接取时关联具体冒险者
- 让日志和最新动态开始出现冒险者名字
- 新增冒险者页签，只显示玩家当前已知的人

## 明确不做

- 完整属性面板
- 礼物系统
- 好感度数值成长
- 定向委派
- 装备系统
- 书信和通信

## 关键规则

- 玩家不是上帝，不会直接知道所有冒险者
- 冒险者页本质上是玩家逐步建立起来的人脉名册
- 信息量取决于接触深度，而不是系统默认全开放
- 这次先做“认识人”，不做深层培养

## 验收标准

- 玩家初始看不到完整冒险者列表
- 至少有一部分冒险者会在任务接取后被玩家认识
- 冒险者页能按认知层级显示不同信息量
- 日志中出现具体冒险者名字
- 构建仍然可以通过

## 风险和待定问题

- 后续“听闻”是靠传闻系统还是靠日志自然解锁，目前仍较粗糙
- 信息层级如果设计得太少，容易又变成普通人物列表
- 信息层级如果设计得太细，早期 UI 可能会显得空

## 跨版本待处理

- 任务页右侧任务列表区域当前仍然容易出现滚动条，后续应优先改为更弹性的比例布局，而不是依赖固定像素宽度
- 任务页滚动任务列表时，“任务列表”标题也会一起滑出视野，后续应考虑做成固定标题或分离滚动容器
- 顶部“村庄据点原型”区域目前占用空间偏大，但承载的信息偏少，后续需要统一压缩信息密度和头部高度
- 当前冒险者偏好直接显示内部资源 id，例如 `wood`、`food`，后续应统一走资源文本映射而不是直接暴露内部字段
- 当前任务与冒险者偏好使用的资源标识，后续应和市场/材料系统共用同一套资源定义，避免出现多套命名体系
- 后续新增系统时，应默认优先拆分配置层、文本层、规则层和渲染层，而不是继续把内容堆回单一文件

## 结果记录

- 已新增少量预设冒险者配置，来源于 [adventurers.json](/home/windflying/Code/AdventureHouse/config/adventurers.json)

- 日常任务现在会由具体冒险者接取，而不再是匿名自动推进
- 日志和最新动态开始出现冒险者名字

- 冒险者近况中的任务编号已改为展示编号，不再直接暴露内部任务 id
- 任务创建、估时、承接与推进细节已从 [dayLoop.ts](/home/windflying/Code/AdventureHouse/src/game/systems/dayLoop.ts) 拆到 [taskBoard.ts](/home/windflying/Code/AdventureHouse/src/game/systems/taskBoard.ts)，`dayLoop` 只保留按天推进编排
