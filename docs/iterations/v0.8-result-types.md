# v0.8 Result Types

## 本次目标

把当前任务完成后几乎都落成“获得资源”的单一结果，扩展成更适合区分补货、调查、异常任务的多种结果类型。

## 本次范围

- 区分“即时资源回报”和“进度型回报”
- 让补货 / 日常任务继续主要产出资源
- 让调查 / 异常任务开始支持非资源结果
- 为后续线索、发现、任务解锁、地区推进预留结果结构

## 明确不做

- 完整主线任务系统
- 完整地图系统
- 完整事件链系统
- 复杂市场回报
- 组队结果结算

## 关键规则

- 任务结果不应长期只有一种
- 调查 / 异常任务可以账面赔本，但不应长期只给“空气”
- 进度型回报应被玩家明确感知，而不是埋在普通文本里
- 当前版本先验证“结果分层”本身，不追求内容量
- 对于系统已知不可执行的操作，优先用前置禁用和状态提示，而不是事后弹错

## 预期方向

- 补货 / 日常：
  - 资源
  - 稳定经营回流

- 调查 / 异常：
  - 线索
  - 发现记录
  - 新任务解锁标记
  - 调查推进
  - 也可能暂时没有实物收益

## 验收标准

- 任务完成后不再只剩一种回报形式
- 玩家能感知补货任务和调查任务在结果上的区别
- 非资源回报不会被误读成普通叙事文本

## 风险和待定问题

- 如果结果类型过多但没有清晰展示，玩家会难以理解收益结构
- 如果调查任务经常没有直接收益，前期可能会显得吃亏

## 跨版本待处理

- 后续应把结果类型接到主线碎片、地图推进、地区解锁、非现金奖励等系统
- 后续应把关键结果纳入高亮规则，避免重要发现被淹没
- 后续应支持“任务认知更新”：冒险者带回的反馈应优先更新玩家对任务的理解，而不是频繁复制同任务变体
- 后续若引入不同冒险者对同一任务的不同判断，应优先记录为观察/认知层，而不是直接改写任务本体
- 每日动态后续可加入筛选，但当前优先保证结果型事件的可见顺序
- 任务“推进”文案后续更适合从“剩余几天”逐步过渡到“已外出几天 / 暂未归来”这类更弱提示的表达
- 随机线索池后续不应长期保持纯随机重复；应逐步支持多条文本、重复追加语和最大出现次数

- 异常任务完成后会记录发现，不再默认只回资源

- 日志高亮已接入“线索 / 发现”两类结果，避免非资源回报被误读成普通叙事文本
- 调查 / 异常任务模板已支持“唯一占用”发布规则，在结果返回前不能重复发布同模板委托

- 已新增独立的消息板页签，自动沉淀线索与发现，不再只让它们停留在日志与任务卡片里
- 线索 / 发现记录现在会保留来源任务与记录日期，方便后续接“可跟进状态”和后续效果
- 本版本如需继续引入测试专用链式标记或结果控制字段，应同步登记到 `testing-artifacts.zh-CN.md`
- 已加入最小任务后续链测试：调查任务可按前置任务结果解锁新的后续模板
- 当前测试链先使用可控成功/失败结果，不依赖随机，用于验证“结果会改变任务池”这件事
- 带后续链的前置调查模板在完成后会从发布列表中退出，避免前置与后续同时长期并存
- 日志与今日动态里的任务相关文本已统一改成“任务代号 + 任务名”，减少跨界面对照成本
- 今日动态已加入结果优先排序：完成 / 失手 / 线索 / 发现 / 后续靠前，推进类事件靠后
- 今日动态标签颜色已拉开，完成、失败、线索、发现、后续、推进等事件不再大量共用同类颜色
- 任务发布表单已开始按任务类型分型：补货 / 日常继续使用“数量 + 预算”，调查 / 异常改成“调查委托”模式，不再按数量收货
- 调查 / 异常任务卡的目标展示也已同步切换到“关注某类线索”，不再伪装成普通收集单
- 调查 / 异常任务已从旧的 `resource` 目标抽离，改为使用 `focusText` 表示调查主题，不再默认绑定经济资源
- 消息板已加入消息状态：没有后续时显示“仅记录”，能带出后续但还没真正接上时显示“可继续跟进”，对应后续任务已经出现后显示“已触发后续”
- 任务配置已开始按主题多文件加载，当前拆成 `base / forest / mine / river / town`
- 已加入统一开启条件骨架，后续主线可逐步从“任务成功/失败”扩展到“线索 / 发现 / 其他条件驱动”
- 已开始引入独立线索库：任务不再必须直接写死线索文本，而可以通过 `resultIntelId / failureIntelId` 引用 `config/intel/*.json` 中的内容
- 森林与河谷测试链已从“看前置任务结果”切换为“看指定线索是否已获得”，`intelReceived` 触发链已完成一轮可测实现
- 已继续扩充森林与河谷的测试线索库，并各自新增一条由前一条线索触发的后续调查任务，验证线索链不会只停在单跳
- 线索板已开始补“所属线 / 来源任务 / 获得方式”这类归属信息，避免线索长期表现成孤立文本碎片
- 已加入 `unlockMode: "any"` 的实际测试链，验证“任意一条线索即可开启同一条后续任务”这条结构不只停留在文档层
- 已加入 `resultIntelPoolIds` 随机线索池与 `resolutionVisibility` 完成后可见性控制，并用一条可重复刷线索的调查任务验证两者组合
- `town-rumors` 已从 `base` 拆成独立主题文件，`旧矿道遗物搜寻` 也已拆到独立 `mine` 主题，用于测试“异常但暂时没有后续”的独立任务线
- 已新增 `validation` 独立主题，用于承载缺线索引用、缺失败回报等配置边界样例，不再把这类内容混进正常任务线
