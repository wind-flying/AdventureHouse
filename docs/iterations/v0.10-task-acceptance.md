# v0.10 Task Acceptance

## 文档用途

这份文档用于承接 `v0.9` 之后的下一条主线：

- 不继续扩任务结算结果层
- 先把“谁会接任务、为什么接、玩家如何看出意向”做成正式骨架

这版的作用，是把“冒险者从看到任务到决定接下”的前半段收稳，让系统真正从“发任务 -> 结算”过渡到“发任务 -> 接任务 -> 结算”。

## 预计主目标

在 `v0.9` 的结算骨架稳定后，优先补“接任务阶段”的正式结构。

换句话说：

- `v0.9` 解决“任务到底怎么算”
- `v0.10` 解决“谁会接任务，以及玩家如何逐步看懂这个人”

## 计划处理项

- 接任务公式正式收口
- 明确接任务阶段真正需要吃哪些输入
- 让人格在接任务阶段的分工更清楚
- 让玩家能从若干次接任务结果中逐步读出冒险者主要意向
- 为后续随机冒险者 / 随机任务提供稳定前置

## 不在这版优先处理

- 结果可解释性增强
- 部分成功 / 部分失败
- 伤病与长期代价
- 线索质量、线索来源更复杂地影响结果
- 任务结果与消息回传的更细耦合
- 对结算结果的 UI 解释补强
- 更成熟的测试矩阵与内容校验工具
- 组队
- 冒险者之间关系
- 自由贸易市场
- 冒险者自主经济循环
- 完整地图
- 长期命运闭环

这些内容应继续保持在后续版本中，不应挤占当前这条“接任务正式化”主线。
