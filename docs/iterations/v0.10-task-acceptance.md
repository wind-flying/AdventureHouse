# v0.10 Task Acceptance

> 后续状态：本版当时使用的接取技术矩阵和模拟脚本已在 `v0.13` 内容重构后正式退役。接取公式本体仍保留在 `src/game/systems/quests/taskAcceptance.ts`，并由 `v0.13` 的熟人 / 新人 / 无人接路由层继续调用。

## 本次目标

在 `v0.9` 的任务结算骨架稳定后，优先把“接任务阶段”收成正式可保留结构。

这版要解决的不是“任务最后怎么结算”，而是：

- 谁会接任务
- 为什么会接
- 玩家能否从若干次接任务结果中逐步看出一个冒险者的主要意向

换句话说：

- `v0.9` 解决“任务到底怎么算”
- `v0.10` 解决“谁会接任务，以及玩家如何开始看懂这个人”

## 本次范围

- 接任务公式正式收口
- 明确接任务阶段真正需要吃哪些输入
- 明确“愿不愿意考虑任务”和“考虑后谁更可能接下”的分工
- 让人格在接任务阶段的职责更清楚
- 明确能力如何进入接任务阶段的主观评估，而不是只留在任务结算阶段
- 让当前接任务逻辑足以支撑后续随机冒险者 / 随机任务

## 明确不做

- 结果可解释性增强
- 部分成功 / 部分失败
- 伤病与长期代价
- 线索质量、线索来源更复杂地影响结果
- 任务结果与消息回传的更细耦合
- 对结算结果的 UI 解释补强
- 更成熟的测试矩阵与内容校验工具
- 随机冒险者正式上线
- 随机任务正式上线
- 好感 / 关系深化
- 任务中间过程真实性
- 组队
- 市场

## 关键规则

- 这版的核心是“接任务阶段正式化”，不是继续补结算公式
- 人格在这版主要服务于：
  - 接不接任务
  - 偏向什么任务
  - 是否容易参与稳定合作
- 能力可以参与接任务公式
  - 但进入的不是“客观结算结果”，而是“冒险者对自己是否做得到的主观评估”
- 接任务阶段的人格与能力分工应保持：
  - 能力提供“这个人客观上更擅长什么”
  - 人格决定“他如何理解自己的能力，以及如何解释任务风险”
- 允许出现这种情况：
  - 高勇气的人，更容易按自己的优势能力去判断“我能做”
  - 高审慎的人，即使客观能力已经不低，面对高风险任务也仍可能提高顾虑
- 当前不要求把这种评估做成复杂心理模型
  - 只要求先建立长期可保留的分工接口
- 当前版本里的“不想接”应理解为：
  - 在默认状态下，这个人主观上不愿意优先选择这类任务
  - 而不是“无论发生什么都绝不会接”
- 从故事性上，人物在一定条件下去做自己本来不想做的事是合理的：
  - 例如资源压力
  - 关系压力
  - 还债、维持声誉、履约义务
- 但这些“被迫去做”的来源，不在这版正式实现
  - `v0.10` 只先建立默认意向骨架
  - 后续如果引入经济压力、关系纠缠、信誉负担，再作为额外状态层压到接任务阶段
- 因此这版的接任务结果应优先表达：
  - 谁更愿意主动去接
  - 谁会犹豫
  - 谁通常不想碰
  - 而不是提前把“被逼着也会干”的所有例外条件一次做完
- 当前不要求玩家直接看到数值
- 当前更重要的是让玩家通过少量样本读出人物意向
- 版本顺序只是开发顺序，不是玩家体验顺序
  - 玩家首次接触可玩版本时，会同时接触当时已完成的多层系统
  - 因此这版的骨架必须考虑后续系统叠加后的整体成立，而不是假设玩家会先单独熟悉一个简化版本
- 任务不应默认都属于同一种筛选强度
  - 有些任务本来就是面向广泛人群的公共任务
  - 有些任务则应明显筛出更窄的人群
- 这版的接任务公式应优先服务“人群倾向”
  - 先回答哪类人通常更愿意接什么
  - 再为少数个体例外预留接口
- 因此“多数人都能接”的公共任务不自动视为错误
  - 只要公共任务内部仍有稳定排序即可
  - 真正需要锋利分化的是筛选型任务
- 接任务逻辑应至少保留两阶段：
  - 是否愿意考虑任务
  - 在愿意接的人里，谁更可能接下
- 当接任务公式需要使用分段或区间偏好时：
  - 必须优先使用连续函数
  - 不应引入会造成体感突变的硬断点
- 这版允许保留线性骨架
  - 但报酬感知、时长偏好、风险感知这类更接近人类主观体感的部分，应优先改成连续曲线
- 测试内容仍只应用于绕过前置、直接验证当前模块
- 如果某项验证能直接从公式分析推出，就不应继续膨胀成长期测试模式

## 验收标准

- 接任务逻辑不再只是“临时能跑”的写法
- 玩家可从少量接任务结果中逐步看出人物主要意向
- 人格在接任务阶段的职责分工清楚，不与能力层混写
- 代码结构足以支撑后续随机冒险者 / 随机任务
- 这版完成后，不需要再回头重写接任务骨架才能进入下一阶段

## 风险和待定问题

- 如果接任务公式过重，会迅速和后续中间过程、关系系统缠在一起
- 如果人格影响过弱，玩家会很难从接任务结果里看出人物
- 如果人格影响过强，接任务结果会显得过于机械
- 如果能力完全不进入接任务判断，人物会显得“不知道自己会什么”
- 如果能力直接按客观结算方式硬套进接任务，又会让人格层失去存在感
- 如果接任务曲线存在明显断点，人物在相邻任务之间的体感变化会显得不自然
- 如果当前版本把“经济压力 / 关系压力 / 义务压力”一起做进来，会让默认意向和例外状态混在一起，反而不利于先看清人物本身
- 如果这版提前把随机冒险者、好感、市场一起塞进来，范围会失控

## 跨版本待处理

- 随机冒险者与随机任务的正式接入
- 好感 / 关系深化
- 接任务阶段的 UI 解释增强
- 接任务中间过程
- 经济压力、关系压力、义务压力等“违背默认意向也会接”的状态来源
- 与结果层、解释层的更紧耦合
- 市场系统

## 结果记录

- 接任务正式逻辑已从任务板编排中拆出，运行时与模拟共用 `taskAcceptance.ts`
- 接任务公式已引入连续曲线约束：
  - 报酬感知改为连续 `tanh` 曲线
  - 短任务 / 长任务偏好改为连续 sigmoid
  - 审慎对风险的顾虑改为连续幂曲线
- 接任务阈值已从“几乎只看人物常数”改成“人物常数 + 任务相关修正”
  - 是否愿意考虑任务，不再只由固定人格阈值决定
  - 长短任务、危险信号、调查信号、报酬信号已进入阈值层
- 接任务随机扰动已改为对称扰动
  - 不再使用只会把分数单向抬高的噪声
- 接任务选择已开始区分公共任务与筛选任务
  - 公共任务拥有更大的候选窗口和更明显的扰动空间
  - 筛选任务更稳定地落向少数更契合的人群
- 长时补给已不再被视作普通稳定补给的简单延长
  - `supply` 的稳定加成现在会被时长压力、危险和不确定性削弱
  - 长线任务会更明显地从“公共可接”往“定向筛选”滑动
- 接任务技术矩阵已开始明确区分“边界样本”和“深区样本”
  - `acceptance-long-haul-borderline` 允许跨区重叠
  - `acceptance-long-haul` 作为长线深区样本，已把 `short-task-regular` 推到阈值外
- `acceptance-dangerous-hunt` 的主候选已修正为 `high-risk-hunter`
  - `curious-investigator` 不再因为“神秘”标签而挤占纯高危对抗任务的第一位
- 本轮通读后新增记录的边界问题：
  - `curious-investigator` 与 `cautious-earner` 对长线任务仍保留一定接受度
  - 目前更像“人群容忍度仍偏宽”，未必是错误，但后续可继续决定是否要让长线深区再更窄
  - 多数模板人物对补给类任务仍普遍偏宽容
  - 这现在更接近“公共任务”的预期表现，不自动视为错误
  - 但后续仍要继续确认这些公共任务内部的人群排序是否足够稳定
