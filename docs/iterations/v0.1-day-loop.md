# v0.1 Day Loop

## 本次目标

做出第一版可推进时间的原型，确认游戏采用非实时、按天推进的基础模型，并让现有任务系统能挂到这个模型上。

## 本次范围

- 引入“天数”概念
- 允许玩家手动进入下一天
- 让任务至少具备基础持续时间或基础结算逻辑
- 为后续接入冒险者系统预留数据结构
- 让界面能展示当前日期和基础状态变化

## 明确不做

- 完整冒险者 AI
- 完整经济系统
- 市场波动
- 书信与传闻系统
- 重开 / 传承系统
- 多时段或按小时行动

## 关键规则

- 游戏不是实时结算
- 玩家点击后才进入下一天
- 一天是最小主要结算单位
- 任务、状态和事件按天推进
- 后续如果要细分时间，优先考虑“早/午/晚”这类离散时段，而不是秒级或分钟级

## 技术选型

- 前端采用 `Vite + TypeScript + CSS`
- 当前阶段保持纯静态站点，优先保证可直接部署到 GitHub Pages
- 暂不引入后端和数据库
- 配置数据先保留为本地 JSON
- 第一版先用简单状态管理，不急着上框架级状态库

## 验收标准

- 玩家可以明确看到当前是第几天
- 玩家可以点击按钮进入下一天
- 进入下一天后，至少有一个系统状态发生可见变化
- 当前代码结构没有把后续扩展卡死

## 风险和待定问题

- 一天内玩家可执行多少操作还没定
- 任务持续时间是否要在本版本就完全引入还未定
- 现有“发布任务”界面更像资源悬赏，后续可能要重构为更通用的任务模型
- 存档方案暂缓，后续优先考虑“本地缓存 + 文本导出 / 导入”这类适合静态站点的方案
- 当前项目通过项目内 `conda` Node 运行时解决了本地启动问题，但命令仍然偏长，后续可以再封装
