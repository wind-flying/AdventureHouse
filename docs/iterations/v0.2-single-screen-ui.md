# v0.2 Single Screen UI

## 本次目标

把当前长页面原型改为更适合策略游戏的单屏界面，减少滚动，提升信息对照效率。

## 本次范围

- 重构主界面布局
- 引入单屏标签切换
- 固定显示核心摘要信息
- 保留现有按天推进与任务原型逻辑
- 调整任务、库存、日志的展示入口

## 明确不做

- 新增冒险者系统
- 新增建筑系统
- 修改任务底层结算规则
- 修改经济公式
- 引入新资源类型

## 关键规则

- 玩家不需要依赖长页面滚动来查看核心状态
- 日期、资金、推进按钮等摘要信息应始终可见
- 任务、库存、日志应分区展示，通过标签切换访问
- 这次改动只重构信息架构，不扩展玩法

## 验收标准

- 页面在常见桌面尺寸下不需要依赖整体滚动条才能完成主要操作
- 玩家能在一个主界面内完成“看状态、发任务、进下一天、看结果”
- 当前功能没有因为 UI 改造而退化
- 构建仍然可以通过

## 风险和待定问题

- 未来加入冒险者和建筑系统后，标签数量可能继续膨胀
- 单屏布局在较小屏幕上的取舍还需要继续优化
- 现在的日志和总览边界仍然比较粗，后续可能要进一步细分

## 跨版本待处理

- 任务页当前的任务列表区仍有布局刚性，后续应减少固定像素依赖
- 任务列表区域的标题与滚动内容还没有完全分层
- 顶部主标题区的信息密度偏低，后续应统一压缩头部占用
- 任务页与冒险者页的筛选区后续应固定在内容区顶部，不随下方列表一起滚动，避免玩家切换筛选时还要重新滑回顶部
- 日志、消息板、历史任务等长列表后续不应长期一次性全量渲染；更适合默认显示最近一段内容，再通过“加载更多 / 展开更多”逐步查看旧记录

## 当前结构约定

- 当前开发分支为 `feat/single-screen-ui`
- 主界面采用桌面端三栏结构：
  - 左侧为导航切换
  - 中间为主操作与主信息区
  - 右侧为“最新动态”独立区域
- 日常任务采用“内部 id + 展示编号”双层结构：
  - 内部唯一 id 供程序使用
  - 展示编号当前使用 `D{day}-{index}`，例如 `D1-1`
- 任务模板支持两种时间模式：
  - `byDifficulty`
  - `fixed`
- 故事文本已从业务逻辑中抽离，统一放在：
  - [storyText.ts](/home/windflying/Code/AdventureHouse/src/game/text/storyText.ts)
- 游戏代码当前按职责拆分为：
  - [app.ts](/home/windflying/Code/AdventureHouse/src/game/app.ts)
  - [config.ts](/home/windflying/Code/AdventureHouse/src/game/config.ts)
  - [dayLoop.ts](/home/windflying/Code/AdventureHouse/src/game/systems/dayLoop.ts)
  - [state.ts](/home/windflying/Code/AdventureHouse/src/game/state.ts)
  - [types.ts](/home/windflying/Code/AdventureHouse/src/game/types.ts)
  - [ui.ts](/home/windflying/Code/AdventureHouse/src/game/ui/ui.ts)

## 结果记录

- 主界面改为单屏标签切换布局
- 桌面端进一步调整为三栏布局，减少两侧无效空间
- 日志页保留更多历史，方便回溯
- “最新动态”移到独立外侧区域，只显示当前这一天的故事碎片
- 任务页加入发布任务入口
- `main.ts` 已拆为多个模块文件，降低后续阅读和追踪成本
- CSS 已拆分为多个文件，按基础、布局、组件分开维护
- 故事文案已独立成文本层，后续可直接集中修改
- 文案池已支持同一事件多条随机文本
- 日常任务展示编号已改为 `D{day}-{index}`
- 任务数据已预留 `daily/main` 分类位，方便后续接主线任务
- `logic.ts` 已重命名为更明确的 [dayLoop.ts](/home/windflying/Code/AdventureHouse/src/game/systems/dayLoop.ts)
- 日常任务模板已支持 `byDifficulty` 和 `fixed` 两种耗时模式
