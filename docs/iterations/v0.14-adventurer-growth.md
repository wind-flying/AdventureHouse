# v0.14 Adventurer Growth

## 当前状态

本版已从“为冒险者养成铺路”扩展为可实际游玩的**第一版冒险者养成入口**，并完成以下闭环：

- 主界面采用连续分割布局：左侧导航、中央工作区、右侧状态与最新动态
- 任务列表具备稳定排序规则，当天新发布任务优先显示
- 百科新增「冒险者养成」分类，并在首次赠礼后解锁相关条目
- 赠礼系统落地：可从人物页或库存页赠送物品，冒险者会接受或婉拒，收下后携带出任务
- 携带物品可在任务结算失败时触发救场重试，并写入结果说明
- 「问问带了什么」行装界面落地：纸娃娃装备槽、性格化对话、关系分级信息披露
- 装备支持玩家自定义名称，采用 Minecraft/Bukkit 风格 `&` / `§` 格式码；字数限制只计可见文字
- 配置与玩家可见文本进一步拆分至 `config/text/`，并补充编写指南

本页后续章节保留了版本开始时的设计边界；若与本节或「最终实现结果」冲突，以本节和「最终实现结果」为准。

## 本次目标

在 `v0.13` 已经把冒险者立成可长期保存的实例后，开始为“玩家如何持续关注、理解并影响某个冒险者”建立正式入口。

本版顶层意图是：

- 为冒险者赠礼与养成内容建立稳定的界面、信息和操作基础
- 让冒险者从“会接任务的长期对象”进一步成为值得持续观察和经营的对象
- 先收稳玩家识别人、找任务、理解信息的日常路径，再接入更重的关系与成长规则

这版要解决的不是：

- 一次做完完整冒险者养成数值体系
- 立即建立可长期平衡的成长曲线
- 礼物经济、偏好配置和完整关系公式

换句话说：

- `v0.13` 解决“冒险者如何成为稳定实例”
- `v0.14` 解决“玩家如何开始赠送、查看、理解并个性化某个冒险者”

## 本次范围

### 界面与信息架构

- 收稳连续分割布局：
  - 左侧导航、中央主要内容、右侧状态与最新动态形成稳定工作区
  - 切换主要页面时，公共状态和近期反馈保持连续可见
  - 窄屏下允许布局降级，不要求强行维持桌面三栏
- 收稳任务查找基础：
  - 任务按稳定规则排序，减少列表顺序跳动和查找成本
  - 当天刚发布的待接任务优先置顶
- 建立分阶段百科基础：
  - 信息按玩家当前接触和理解阶段逐步公开
  - 百科承接任务说明与冒险者养成说明
  - 新增 `firstAdventurerItemGifted` 解锁条件，并接入真实赠礼行为

### 赠礼与携带

- 从冒险者卡片或库存页打开赠礼对话框
- 冒险者根据熟悉度、物品匹配度和性格倾向决定接受或婉拒
- 接受后物品进入冒险者携带列表，并可能提升认识度
- 出任务时携带物品参与结算；失败时可能触发赠礼救场
- 首次赠礼写入 `player.hasGiftedAdventurerItem`，用于百科解锁

### 行装与装备展示

- 冒险者卡片增加「问问带了什么」入口
- 行装界面左侧为纸娃娃装备槽，右侧为性格化自述
- 按关系阶段控制可见信息：
  - 已接触：可见装备
  - `familiar`：可见携带金钱
  - `trusted`：可见全部携带物品及数量、保质期、使用次数
- 装备显示策划设定的简称；玩家可设置带格式码的自定义名称
- 悬停装备名称时显示策划全名、玩家描述和效果风味文案（不含具体数值）

### 配置与文档

- 装备、物品、资源等玩家可见文本拆至 `config/text/`
- 补充百科、行装对话编写指南
- 登记赠礼测试内容包，便于验证能力增益与携带逻辑

## 明确不做

- 完整等级、经验值或属性点成长系统
- 完整好感值、关系值或亲密度数值条
- 礼物获取、定价、稀有度和市场经济闭环
- 礼物偏好全量配置与平衡
- 赠礼后的完整数值结算与长期关系公式
- 技能树、职业树、装备养成或升阶系统
- 冒险者伤病、衰老、忠诚、背叛等长期模拟
- 任务模板独立简称字段（本版仅完成装备简称与排序，任务简称留待后续）
- 富文本渐变、波浪等超出 `&` / `§` 标准码的动态特效

## 关键规则

### 养成入口

- 本版的“养成”首先指长期关注、赠礼、查看与个性化入口，不等于立即加入成长数值
- 赠礼与养成必须建立在冒险者实例上，不回退到模板级关系
- 玩家经营的是已经进入视野的具体人物，不是抽象职业模板

### 认知与百科

- 新入口复用现有认知阶段：信息公开随认识加深逐步推进
- 百科必须区分玩家已确认的事实、当前印象/传闻，以及尚未公开的内容
- 分阶段公开不是单纯按天数解锁，应优先由实际行为推动
- `firstAdventurerItemGifted` 在首次赠礼成功后置为 `true`，不提前写入无用途占位

### 赠礼

- 出任务中的冒险者暂时不能收礼
- 接受与否受熟悉度、物品兼容性和性格倾向共同影响，不是 deterministic
- 收下后物品写入 `adventurer.giftedItems`，带独立 `giftId`、剩余保质期与剩余使用次数
- 结算失败时，系统按携带顺序尝试消耗物品进行救场；使用后写入 `usedGiftItems`
- 调参集中在 `src/game/systems/gifting.ts` 顶部 `GIFTING_TUNING`

### 行装与对话

- 行装不是背包面板，而是冒险者用自己的语气说明随身情况
- 对话模板按最高性格轴选择；最高与第二高接近时使用 `balanced`
- 占位符 `{itemClause}`、`{equipmentClause}`、`{moneyClause}` 由代码生成完整子句，模板不得自行拼接前后缀
- 对话与列表展示使用 `stripRichTextFormatting()` 取可见纯文本；界面渲染才解析格式码

### 装备名称

- 策划提供 `name`（全名）与 `shortName`（默认简称）
- 玩家 `customName` 可含 `&` / `§` 格式码；可见字数上限 24，格式码不计入
- 留空自定义名则恢复为策划简称
- 自定义名写入装备实例并随存档保存（当前存档格式仍为 `version: 7`）

### 任务排序

- 优先级：当天待接 > 进程中的主线/调查类 > 其他进行中 > 其他待接 > 已完成
- 同优先级内按最近相关日期降序，再按内部 id 稳定排序
- 实现位于 `src/game/ui/questSorting.ts`

### 布局

- 连续分割布局服务于跨页面经营：公共状态和近期反馈不应因切换页面而完全消失
- 各分区有明确滚动边界，避免整页内容互相挤压

## 验收标准

- 桌面布局能够稳定区分导航、主要内容和公共状态 / 最新动态
- 在任务、冒险者和百科相关页面之间切换时，玩家仍能保持当前经营上下文
- 窄屏下主要功能仍可访问，不因分栏布局造成核心内容不可用
- 任务列表具有明确且稳定的排序结果
- 百科信息能够体现阶段差异；首次赠礼后解锁「冒险者养成」条目
- 赠礼、携带、救场和结果展示形成可体验闭环
- 行装界面能按关系阶段正确隐藏或显示金钱与携带物
- 装备自定义名支持格式码渲染，且超限时无法保存
- 冒险者实例、认知阶段、赠礼记录、装备实例和百科展示之间的职责边界清楚
- 未向存档写入没有实际用途的完整成长数值占位

## 风险和待定问题

- 如果“养成”过早等同于经验条和属性点，会在内容目标尚未明确时锁死数值结构
- 如果赠礼只增加单一好感数字，会与现有逐步认识人物的设计脱节
- 如果任务简称缺少稳定来源，后续存档、日志和百科引用会出现同名或改名兼容问题
- 如果百科把传闻和事实混为一谈，会削弱认知阶段与调查结果的价值
- 如果三栏布局的滚动边界不清，连续可见会变成信息拥挤
- 当前仍待确定：
  - 赠礼首先改变认知进度、关系倾向，还是主要触发人物内容
  - 冒险者成长首先作用于能力、行为偏好，还是可公开履历
  - 任务简称由配置显式提供，还是由稳定规则生成并允许覆写
  - 富文本是否扩展自定义动态特效码

## 跨版本待处理

- 任务模板独立简称与高频引用统一
- 礼物来源、库存占用和消耗规则的完整经济闭环
- 冒险者礼物偏好与反馈层级配置化
- 非任务接触和关系推进
- 正式成长维度及其数值模型
- 成长、关系与任务承接 / 结算之间的影响边界
- 特殊人物事件、信件、邀约与定向委派
- 百科内容扩充及地点、资源、任务线等分类
- 赠礼测试内容包在正式内容稳定后的清理或迁移

## 结果记录

- 版本开始时先记录范围，避免把“为养成铺路”扩张成“一次完成全部养成系统”
- 开发过程中范围有所扩展：赠礼与行装从“预留入口”推进为可游玩功能
- 与原计划的范围差异：
  - **超出原计划完成**：赠礼接受/婉拒、携带出任务、失败救场、行装界面、装备富文本改名
  - **按计划完成**：连续分割布局、任务排序、分阶段百科、养成百科解锁接口
  - **尚未完成**：任务模板简称、完整成长/关系数值、礼物经济闭环

## 最终实现结果

### 界面与信息架构

- `src/game/ui/appShell.ts` 使用 `workspace` 三列结构：`sidebar` / `content-stage` / `right-rail`
- 百科、赠礼、行装对话框挂载于主容器，切换 Tab 时不销毁公共上下文
- `src/game/ui/questSorting.ts` 实现任务展示排序

### 赠礼系统

- 入口：
  - 冒险者卡片「赠送物品」
  - 库存页「赠送」
- 核心逻辑：`src/game/systems/gifting.ts`
- 结算接入：`tryResolveFailureWithGiftedItems()` 在 `taskResolution.ts` 失败路径中调用
- 玩家里程碑：`gameData.player.hasGiftedAdventurerItem`
- 结果展示：任务卡片与结果原因中可看到携带物品使用情况

### 行装界面

- 模块：`src/game/ui/loadout.ts`
- 纸娃娃八槽：头盔、武器、盾、护甲、腿甲、靴子、饰品、工具
- SVG 人形与槽位连线；装备卡片可点击改名
- 对话模板：`src/game/text/loadoutText.ts`
- 编写指南：[loadout-dialogue-authoring-guide.zh-CN.md](/home/windflying/Code/AdventureHouse/docs/guidelines/loadout-dialogue-authoring-guide.zh-CN.md)

### 装备展示与自定义名

- 显示逻辑：`src/game/ui/equipmentDisplay.ts`
- 富文本解析：`src/game/text/richText.ts`（`&0`–`&f`、`&#RRGGBB`、`&l` / `&o` / `&n` / `&m` / `&k` / `&r`）
- 效果风味文案：`src/game/text/equipmentEffectText.ts`（描述性语言，不含 `+4` 类数值）
- 实例字段：`equipment.customName`，随存档读写

### 百科

- 配置：`config/encyclopedia.json`
- 文本：`src/game/text/encyclopediaText.ts`
- 判断：`src/game/ui/encyclopedia.ts`
- 新增分类 `growth`（冒险者养成）及三条赠礼相关条目
- 解锁条件：`firstAdventurerItemGifted`
- 编写指南：[encyclopedia-authoring-guide.zh-CN.md](/home/windflying/Code/AdventureHouse/docs/guidelines/encyclopedia-authoring-guide.zh-CN.md)

### 配置与文本分层

- 新增 `config/text/equipment/`、`config/text/items/`、`config/text/resources/` 等
- 装备定义保留结构字段，玩家可见名称与描述由 text 层提供
- 程序读取时合并 config 与 text

### 测试内容

- 赠礼/行装开发期使用的 `gift-test`、`test-novice`、`demo-*` 测试包已删除，回归序章正式内容体验

### 验收结果

- TypeScript 类型检查与生产构建通过
- 桌面与窄屏布局保留明确的模块分割和可访问入口
- 赠礼、行装、百科、任务排序可在序章正式内容下人工体验
- 开发服务器默认仅监听 `127.0.0.1`（见 [local-run.zh-CN.md](/home/windflying/Code/AdventureHouse/docs/iterations/local-run.zh-CN.md)）

### 当前验证方式

- 清空或重置存档后，通过序章任务、制作与市场获得正式物品
- 向已认识冒险者赠送食物或药品，发布调查类任务并观察结算与救场
- 打开冒险者行装界面，验证纸娃娃、自定义装备名与改名计数
- 首次赠礼后打开百科，确认「冒险者养成」分类解锁
