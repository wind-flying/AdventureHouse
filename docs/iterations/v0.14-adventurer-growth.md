# v0.14 Adventurer Growth

## 本次目标

在 `v0.13` 已经把冒险者立成可长期保存的实例后，开始为“玩家如何持续关注、理解并影响某个冒险者”铺设正式入口。

本版顶层意图是：

- 为后续冒险者赠礼与养成内容建立稳定的界面、信息和操作基础
- 让冒险者从“会接任务的长期对象”进一步成为值得持续观察和经营的对象
- 先收稳玩家识别人、找任务、理解信息的日常路径，再接入更重的关系与成长规则

这版要解决的不是：

- 一次做完完整冒险者养成
- 立即建立可长期平衡的成长数值系统
- 立即实现完整赠礼循环

换句话说：

- `v0.13` 解决“冒险者如何成为稳定实例”
- `v0.14` 解决“赠礼与养成内容以后从哪里进入、依赖哪些稳定信息”

## 本次范围

- 收稳连续分割布局：
  - 左侧导航、中央主要内容、右侧状态与最新动态形成稳定工作区
  - 切换主要页面时，公共状态和近期反馈保持连续可见
  - 窄屏下允许布局降级，不要求强行维持桌面三栏
- 收稳任务查找基础：
  - 任务按稳定规则排序，减少任务列表顺序跳动和查找成本
  - 为任务提供适合重复引用的简称
  - 简称用于列表、动态、关系记录等高频场景，不替代正式标题
- 建立分阶段百科基础：
  - 信息按玩家当前接触和理解阶段逐步公开
  - 百科首先承接冒险者、任务及相关发现的长期查阅需求
  - 当前只建立分层展示和后续扩展入口，不要求一次填满百科内容
- 明确后续赠礼与养成所需的最小接口方向：
  - 稳定冒险者实例
  - 可追踪的认知阶段
  - 可引用的任务和事件记录
  - 可逐步公开的人物信息

## 明确不做

- 完整等级、经验值或属性点成长系统
- 完整好感值、关系值或亲密度数值条
- 礼物获取、定价、稀有度和市场经济闭环
- 礼物偏好全量配置与平衡
- 赠礼后的完整数值结算
- 技能树、职业树、装备养成或升阶系统
- 冒险者伤病、衰老、忠诚、背叛等长期模拟
- 大规模新增冒险者、任务或百科文本
- 为未来系统提前写入无法验证的存档字段

## 关键规则

- 本版的“养成”首先指长期关注和内容入口，不等于立即加入成长数值
- 赠礼与养成必须建立在冒险者实例上，不回退到模板级关系
- 玩家经营的是已经进入视野的具体人物，不是抽象职业模板
- 新入口应复用现有认知阶段：
  - 信息公开随认识加深逐步推进
  - 后续赠礼资格、反馈深度和特殊内容可以接入该阶段
  - 本版不提前规定最终关系公式
- 百科必须区分：
  - 玩家已经确认的事实
  - 当前只掌握的印象、传闻或线索
  - 尚未公开的内容
- 分阶段公开不是单纯按天数解锁
  - 应优先由接触、共同任务、结果和后续互动推动
- 任务简称必须稳定、可辨认
  - 同一任务在不同页面使用同一简称
  - 简称不能只靠截断正式标题生成
  - 正式标题仍用于完整叙事表达
- 任务排序必须服务玩家判断
  - 当前可行动、正在推进或需要关注的任务优先于纯历史记录
  - 同一优先级内使用稳定次序，避免无意义重排
- 连续分割布局服务于跨页面经营
  - 公共状态和近期反馈不应因切换人物、任务或百科而完全消失
  - 各分区应有明确滚动边界，避免整页内容互相挤压
- 本版只为未来数值系统保留清楚边界
  - 没有实际玩法消费的字段不提前进入正式状态或存档
  - 后续确定成长规则时，再通过版本迁移增加正式字段

## 验收标准

- 桌面布局能够稳定区分导航、主要内容和公共状态 / 最新动态
- 在任务、冒险者和百科相关页面之间切换时，玩家仍能保持当前经营上下文
- 窄屏下主要功能仍可访问，不因分栏布局造成核心内容不可用
- 任务列表具有明确且稳定的排序结果
- 任务简称能在高频引用场景中一致显示，并能对应回正式任务
- 百科信息能够体现至少一种明确的阶段差异，而不是一次性公开全部内容
- 冒险者实例、认知阶段、任务记录和百科展示之间的职责边界清楚
- 本版结束时，不需要先实现完整养成数值系统，也能继续添加赠礼与人物养成内容
- 未向存档写入没有实际用途的完整成长数值占位

## 风险和待定问题

- 如果“养成”过早等同于经验条和属性点，会在内容目标尚未明确时锁死数值结构
- 如果赠礼只增加单一好感数字，会与现有逐步认识人物的设计脱节
- 如果任务简称缺少稳定来源，后续存档、日志和百科引用会出现同名或改名兼容问题
- 如果任务排序只按创建时间，任务量增加后仍会掩盖当前需要处理的事项
- 如果百科把传闻和事实混为一谈，会削弱认知阶段与调查结果的价值
- 如果三栏布局的滚动边界不清，连续可见会变成信息拥挤
- 当前仍待确定：
  - 赠礼首先改变认知进度、关系倾向，还是触发人物内容
  - 冒险者成长首先作用于能力、行为偏好，还是可公开履历
  - 百科的正式内容边界是否只覆盖人物，还是同时覆盖任务线、地点和资源
  - 任务简称由配置显式提供，还是由稳定规则生成并允许覆写

## 跨版本待处理

- 礼物来源、库存占用和消耗规则
- 冒险者礼物偏好与反馈层级
- 非任务接触和关系推进
- 正式成长维度及其数值模型
- 成长、关系与任务承接 / 结算之间的影响边界
- 特殊人物事件、信件、邀约与定向委派
- 百科内容扩充及地点、资源、任务线等分类
- 新增长期状态后的存档迁移

## 结果记录

- 版本开始时先记录范围，避免把“为养成铺路”扩张成“一次完成全部养成系统”
- 本版已经具备的基础工作：
  - 连续分割布局：主要导航、内容工作区、公共状态和最新动态已拆成稳定区域
  - 任务排序 / 简称：已进入任务信息收口范围，作为后续日志、百科和人物经历引用的统一基础
  - 分阶段百科：已进入信息架构范围，继续沿用“随接触和理解逐步公开”的原则
- 当前实现结果：
  - 主界面模块改为相邻分割布局，以横线和竖线明确区分导航、主要内容、状态和动态
  - 任务列表按进程任务、日常运维、等待接取和历史完成记录组织；当天刚发布的任务保持置顶
  - 任务模板支持独立简称，发布选择框不再依赖完整标题
  - 百科采用配置、玩家文本和解锁判断分层
  - 首批任务百科在首次发布任务后解锁，并通过右上角提示按钮提醒
  - 已预留首次赠送冒险者物品后的养成百科解锁条件
- 验收结果：
  - TypeScript 类型检查和生产构建通过
  - 桌面与窄屏布局保留明确的模块分割和可访问入口
  - 百科支持遮罩、关闭按钮和 Escape 关闭
- 与原计划的范围差异：
  - 本版未实现实际赠礼和成长数值，只完成其内容入口与解锁接口
- 遗留问题与后续版本入口：
  - 赠礼行为落地后，将实际行为事实接入 `firstAdventurerItemGifted`
  - 后续增加养成条目时继续复用现有百科配置和文本边界
