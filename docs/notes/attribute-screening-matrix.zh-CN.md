# 属性与任务特征筛选表

## 文档用途

这份文档不是最终属性定稿，而是给 `v0.9` 后半段做筛选用的工作表。

目标是：

- 先把常见要素列出来
- 再把本项目更独特、更贴“碎片叙事 / 间接影响冒险者”方向的要素列出来
- 然后逐项判断它们是否值得保留

最终不是追求“列得越多越好”，而是：

- 每个保留下来的属性都有清晰存在理由
- 每个保留下来的任务特征都能支持后续公式
- 尽量减少没有主场、没有特点、只是重复别人的属性

## 使用规则

后续筛选时，每个候选项都至少看这几件事：

1. 它服务哪类公式
2. 它是不是某类公式的主场因素
3. 它和现有项是否高度重复
4. 玩家是否需要感知它
5. 如果砍掉它，会损失什么

当前状态列建议这样理解：

- `保留`
  - 已经有较明确存在理由，后续应优先进入第一版骨架
- `待观察`
  - 有价值，但目前还不确定是否和其他项重叠，或是否现在就该加
- `删除候选`
  - 当前看不出清晰主场，或和别的项重叠太强

## 三、人格层与能力层的潜在重叠点

这部分不是要求立刻删，而是提醒后续正式落属性时要避开。

| 人格属性 | 容易重叠的能力属性 | 当前判断 |
| --- | --- | --- |
| 勇敢 | 战斗、意志 | 后续应区分“敢不敢上”和“能不能打” |
| 审慎 | 观察、生存 | 后续应区分“会不会规避风险”和“能不能处理风险” |
| 求知 | 观察、求知能力 | 后续应区分“想不想研究”和“有没有研究能力” |
| 韧性 | 生存、体魄 | 后续应区分“愿不愿意熬”和“身体能不能扛” |
| 社交 | 交涉 | 后续应区分“乐不乐意接触人”和“会不会谈” |

## 四、1.0 阶段收束后的第一版骨架倾向

按目前讨论，并收束到“1.0 先服务玩家与单个冒险者关系、单人任务表现、不先服务组队和市场”之后，后续第一版更可能优先保留的组合是：

### 任务隐藏特征

- 危险性
- 难度
- 耗时压力
- 未知度
- 调查复杂度
- 信息回传难度
- 稳定性

### 冒险者正式能力

- 体魄
- 生存
- 探索
- 观察
- 战斗

### 暂时更适合留在后面的

- 交涉
- 求知能力
- 手艺
- 社交需求
- 长线消耗
- 致命性
- 道德负担

## 五、当前建议方案

### 目标

先把 `1.0` 阶段真正需要的那批输入做稳定：

- 让单个冒险者“为什么接、为什么成、为什么败”更清楚
- 让线索不只负责解锁，还能开始影响任务判断和结果质量
- 让后续成长系统知道自己到底在提升什么

### 当前建议方向

1. 先补任务隐藏特征层
   - 不再长期只靠：
     - 风险
     - 难度
     - 耗时
   - 而是扩成：
     - 危险性
     - 未知度
     - 调查复杂度
     - 稳定性
     - 信息回传难度
     - 耗时压力

2. 再把冒险者正式能力稳定为 5 项
   - 体魄
   - 生存
   - 探索
   - 观察
   - 战斗

3. 人格层暂时继续保留
   - 不并进能力层
   - 主要负责：
     - 主观风险判断
     - 自我能力评估偏差
     - 接取意愿

4. 公式上分工明确
   - 任务接取：
     - 人格为主
     - 能力和任务特征进入主观评估
   - 任务结算：
     - 任务特征 + 实际能力为主
     - 人格只做少量稳定性/判断风格修正

### 为什么这样收

- 这批属性已经足够支撑 `1.0`
  - 单人任务表现
  - 玩家培养感
  - 线索对结果的帮助
- 但还没有提前为：
  - 组队
  - 市场
  - 冒险者之间关系
  这些后续系统背过多包袱

### 当前不建议马上做的

- 再继续加更多能力名词
- 过早引入幸运、意志、速度这类容易重复的项
- 为未来组队/市场先预埋太多属性
- 把人格和能力混成一张大属性表

## 六、后续使用方式

后续如果准备正式扩属性与任务特征，建议按这个顺序推进：

1. 先从“当前第一版骨架倾向”里选最小集合
2. 写清每一项要进入哪类公式
3. 确认没有两个属性长期完全共享主场
4. 再进入代码层改造

也就是说，这张表的作用不是一次把所有内容定死，而是帮助后续每次新增属性时都先经过一轮筛选，而不是直接往代码里塞。
